# Launch rehearsal and capstone acceptance

[Course home](../README.md)

Use **verified**, **needs revision**, or **not tested** for every item. These fields describe your future implementation; they are not claims that a storefront or campaign has already been tested.

## 1. Strategy coherence

- [ ] The buyer is a specific situation and knowledge level, not “everyone.”
- [ ] Research notes distinguish observed behavior from speculation.
- [ ] Positioning describes a useful, supportable difference.
- [ ] The offer solves a bounded problem that the product actually teaches.
- [ ] The sample represents the paid material's level and quality.
- [ ] The chosen channel reaches people with that problem.

## 2. Product readiness

- [ ] A new learner can identify the starting point.
- [ ] Prerequisites and setup assumptions are visible.
- [ ] Included files match the offer specification.
- [ ] Important examples have been verified appropriately.
- [ ] Navigation and reference material work.
- [ ] Version-sensitive claims are identified.
- [ ] Rights and permissions for included material are appropriate.
- [ ] Update and support commitments fit available capacity.

## 3. Sales-page readiness

- [ ] The audience, outcome, format, and prerequisites are clear.
- [ ] The sample and content links work.
- [ ] The price, currency, and applicable display details are understandable.
- [ ] Delivery timing and access duration are stated.
- [ ] Support, update, licensing, and refund/cancellation terms are completed.
- [ ] No invented reviews, unsupported results, or artificial scarcity appear.
- [ ] The page is usable on a phone and through keyboard navigation.
- [ ] A relevant reader can explain what they expect after paying.

## 4. Email and measurement readiness

- [ ] Signup text matches the real subscription and delivery process.
- [ ] Any applicable consent/confirmation process works.
- [ ] Authentication is configured according to the provider's current instructions.
- [ ] Sample delivery and welcome links work.
- [ ] Opt-out and suppression behavior have been tested.
- [ ] Buyers stop receiving inappropriate offers for the same product.
- [ ] Events have clear definitions and only necessary fields.
- [ ] Payment records and confirmed-purchase reporting reconcile in a controlled test.
- [ ] Campaign names are consistent.
- [ ] Relevant privacy and policy requirements have been checked for the actual implementation.

## 5. Transaction rehearsal

| Scenario | Expected behavior | Actual result | Status and correction |
| --- | --- | --- | --- |
| Successful supported test purchase | Correct amount, one order, appropriate access |  |  |
| Failed payment | Clear retry path, no false purchase confirmation |  |  |
| Duplicate/reloaded confirmation | No duplicate order reporting |  |  |
| Buyer access problem | Functioning support and recovery path |  |  |
| Refund under stated terms | Correct financial and access handling |  |  |
| Existing subscriber purchases | Appropriate onboarding and sequence changes |  |  |
| Newsletter opt-out | Promotional suppression works |  |  |
| Mobile checkout | Offer and terms remain usable |  |  |

Use the platform's supported test process. Do not expose real payment data in screenshots or course materials.
